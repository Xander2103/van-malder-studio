# Van Malder Studio — vanmalderstudio.be

Laravel 12 + Vite/Tailwind 4 marketing site (NL / FR / EN / DE) for Van Malder Studio.

## Deployment

Production runs from a plain Git checkout on the VPS (`/var/www/vanmalderstudio`, branch `main`).
Every future update is deployed with one command **on the server**:

```bash
cd /var/www/vanmalderstudio
./deploy.sh
```

The script (see `deploy.sh`) does, in order:

1. Verifies it runs inside this project (`artisan`, `composer.json`, `package.json`, `.env` present) and that `.env` has `APP_ENV=production`.
2. Checks the checked-out branch is `main` and the working tree is clean — **it stops with a warning if there are uncommitted server-side changes** (nothing is ever discarded).
3. Prints the current commit, `git fetch` + `git merge --ff-only origin/main`, prints the new commit and the changelog.
4. `composer install --no-dev --optimize-autoloader`, `npm ci`, `npm run build` (fails hard if `public/build/manifest.json` is missing).
5. `php artisan down` → `migrate --force` → `optimize:clear` → `config/route/view/event:cache` → `storage:link` (if missing) → `php artisan up`. A shell trap brings the site back up if any step fails.
6. Sets `storage/` and `bootstrap/cache/` to group `www-data` with `ug+rwX` — nothing else is chowned/chmodded.
7. Optionally reloads PHP-FPM (`RELOAD_CMD`), then prints `artisan about` and curls `APP_URL/nl` as a smoke check.

Optional overrides: `APP_DIR`, `BRANCH`, `WEB_GROUP`, `RELOAD_CMD` (e.g. `RELOAD_CMD="sudo systemctl reload php8.3-fpm" ./deploy.sh`), `SKIP_NPM=1`.

**One-time server prerequisites** (not handled by the script):

- The deploy user must be able to `git fetch` from GitHub (SSH key or deploy key) and must own the checkout.
- `composer`, `npm`/Node and `php` must be on the deploy user's `PATH`.
- If the deploy user is not in the `www-data` group, allow password-less `sudo chgrp/chmod` on `storage` and `bootstrap/cache`, or set `WEB_GROUP` to the correct group.
- If OPcache is enabled with `validate_timestamps=0`, set `RELOAD_CMD` so PHP-FPM is reloaded after each deploy.
- `.env` is never written by the script — update `APP_URL`, mail settings, etc. by hand.

Rollback: the script prints the commit hash before and after. To roll back, revert on `main` (e.g. `git revert <sha>`), push, and run `./deploy.sh` again.

## Local development

```bash
composer install && npm install
cp .env.example .env && php artisan key:generate
php artisan migrate
composer run dev      # serve + queue + logs + vite
php artisan test      # test suite
vendor/bin/pint       # code style
```

SEO-relevant configuration lives in `config/studio.php` (business identity, `same_as` profile URLs, `area_served`), `config/client-work.php` (real client projects; add a screenshot path under `image`), `config/projects.php` (own projects) and `config/landing-pages.php` (NL local/service landing pages). `robots.txt` and `sitemap.xml` are generated by `PageController` — do not add static copies in `public/`.

## About Laravel

Laravel is a web application framework with expressive, elegant syntax. We believe development must be an enjoyable and creative experience to be truly fulfilling. Laravel takes the pain out of development by easing common tasks used in many web projects, such as:

- [Simple, fast routing engine](https://laravel.com/docs/routing).
- [Powerful dependency injection container](https://laravel.com/docs/container).
- Multiple back-ends for [session](https://laravel.com/docs/session) and [cache](https://laravel.com/docs/cache) storage.
- Expressive, intuitive [database ORM](https://laravel.com/docs/eloquent).
- Database agnostic [schema migrations](https://laravel.com/docs/migrations).
- [Robust background job processing](https://laravel.com/docs/queues).
- [Real-time event broadcasting](https://laravel.com/docs/broadcasting).

Laravel is accessible, powerful, and provides tools required for large, robust applications.
